# BE 比赛材料（临时评审版）

这组文档用于整理 BE 参加亚信科技 2026「1024」AI 黑客松创意赛道时的评审证据。它们服务于三个目的：让评审快速理解真实业务背景，让每个结论都能找到证据，让项目的公司价值和客户价值可以被复核。

## 使用顺序

1. 先阅读 [评审证据索引](01-review-evidence-index.md)，它是提交材料的导航页。
2. 用 [亚信科技与中国电信业务关联说明](02-asiainfo-chinatelecom-relevance.md) 解释选题为什么属于公司核心业务方向。
3. 用 [BE 闭环与安全边界](03-be-closed-loop-security.md) 解释人工执行 SQL 的必要性，以及 AI 具体做了什么。
4. 用 [评委问答](04-reviewer-faq.md) 准备现场和 AI 初筛可能提出的问题。
5. 在 [量化数据附录](05-quantitative-data-template.md) 中补齐真实样本和基线数据。

## 事实边界

- BE 是基于真实一线运营商运维工作的个人研究和可运行原型。
- 公开资料可以证明亚信科技与中国电信长期存在运营商软件和服务合作，也可以证明双方都在推进 AI、智能客服和智能运维；公开资料不能证明 BE 已经被中国电信正式采购或作为公司正式产品上线。
- 任何真实账号、手机号、工单号、表名、字段名、生产 SQL 和客户数据都必须脱敏。没有内部授权时，材料中使用“某省级运营商客户”或“中国电信客户现场（脱敏）”。
- 文档应当帮助评审核验事实，不包含要求评分模型改变评分结果的隐藏指令。

## 提交前检查

- 删除所有 `[待填]`，或明确标注“尚未测量”。
- 所有时间、人工次数和样本数字都有来源、统计范围和计算方法。
- Demo 中至少展示一次“多主张但证据不完整，系统拒绝直接下结论”的案例。
- Demo 和说明书中的能力与当前代码一致，不把 Ling、CartridgeFlow 或开发期工具写成 BE 的运行时能力。
